# ZTForensics Setup Guide

## Prerequisites

- Docker 24+ and Docker Compose v2
- Python 3.10+ (for helper scripts)
- `curl` and `bash` (for setup scripts)
- At least 4 GB of available RAM and 10 GB of disk space

---

## Quick Start (one command)

```bash
cp .env.example .env
docker compose up -d
bash scripts/setup_keycloak.sh
```

Open your browser at **http://localhost:5000**.

---

## Step-by-Step: Development Setup

### 1. Clone and configure

```bash
git clone https://github.com/alishancyber-eng/ztforensics.git
cd ztforensics
cp .env.example .env          # or copy .env.development for dev defaults
```

Edit `.env` and customise any values you need (see [Environment Configuration](#environment-configuration) below).

### 2. Start all services

```bash
docker compose up -d
```

This starts:
| Service | URL |
|---------|-----|
| PostgreSQL (app) | `localhost:5432` |
| PostgreSQL (Keycloak) | `localhost:5433` |
| Keycloak | http://localhost:8080 |
| MinIO API | http://localhost:9000 |
| MinIO Console | http://localhost:9001 |
| OPA | http://localhost:8181 |
| API Gateway | http://localhost:8000 |
| Dashboard | http://localhost:5000 |

### 3. Wait for services to become healthy

```bash
docker compose ps
```

All services should show `healthy` after about 60–90 seconds.

### 4. Set up Keycloak

```bash
bash scripts/setup_keycloak.sh
```

This script will:
- Create the `forensics` realm
- Create the `api-gateway` client
- Create roles: `investigator`, `analyst`, `auditor`, `admin`, `viewer`
- Create a test user `testuser` / `testpass123` with the `investigator` role
- Print the generated client secret

Copy the printed `KEYCLOAK_CLIENT_SECRET` value into your `.env` file, then restart the API:

```bash
docker compose restart ztf-api
```

### 5. Initialise the database (optional)

The API Gateway automatically creates the schema on first start. To run the
initialisation script manually (e.g. to add custom indexes):

```bash
bash scripts/init_database.sh
```

### 6. Verify everything is healthy

```bash
bash scripts/health_check.sh
```

## Step-by-Step: Production Setup

> **Security note:** Always rotate all passwords, secrets, and keys before deploying to production.

### 1. Copy the production template

```bash
cp .env.production .env
```

Replace every `REPLACE_WITH_*` placeholder with strong, unique values:

```bash
# Generate a random secret key
python3 -c "import secrets; print(secrets.token_hex(32))"
```

### 2. Configure TLS

Place your TLS certificate and key in a directory accessible to Keycloak (e.g. `./certs/`) and update `KC_HOSTNAME` and `KC_HTTPS_*` variables in `docker-compose.yml` or override them via `.env`.

For a simple reverse-proxy setup, place Nginx or Caddy in front of the services and point them to the internal Docker network.

### 3. Change the default Keycloak admin credentials

Set `KEYCLOAK_ADMIN_USER` and `KEYCLOAK_ADMIN_PASSWORD` in `.env` **before** the first start.

### 4. Start services

```bash
docker compose -f docker-compose.yml up -d
bash scripts/setup_keycloak.sh
bash scripts/health_check.sh
```

### 5. Enable automated backups

Schedule `scripts/backup.sh` with cron or a CI/CD scheduler:

```cron
0 2 * * * /bin/bash /opt/ztforensics/scripts/backup.sh >> /var/log/ztforensics-backup.log 2>&1
```

## Environment Configuration

| Variable | Default | Description |
|---|---|---|
| `KEYCLOAK_SERVER_URL` | `http://localhost:8080` | Keycloak base URL |
| `KEYCLOAK_REALM` | `forensics` | Realm name |
| `KEYCLOAK_CLIENT_ID` | `api-gateway` | Client ID |
| `KEYCLOAK_CLIENT_SECRET` | *(empty)* | Client secret (generated by setup script) |
| `KEYCLOAK_ADMIN_USER` | `admin` | Admin username |
| `KEYCLOAK_ADMIN_PASSWORD` | `admin123` | Admin password – **change this** |
| `DATABASE_URL` | `postgresql://ztf:ztfpass@ztf-postgres:5432/ztfdb` | PostgreSQL connection string |
| `MINIO_ENDPOINT` | `ztf-minio:9000` | MinIO host:port |
| `MINIO_ACCESS_KEY` | `minioadmin` | MinIO access key |
| `MINIO_SECRET_KEY` | `minioadmin123` | MinIO secret key |
| `OPA_URL` | `http://ztf-opa:8181` | OPA base URL |
| `SECRET_KEY` | *(placeholder)* | App secret – **change this** |
| `DEBUG` | `False` | Enable debug mode |
| `CORS_ORIGINS` | `http://localhost:5000,...` | Allowed CORS origins |
| `LOG_LEVEL` | `INFO` | Log verbosity |
| `LOG_FORMAT` | `json` | Log format (`json` or `text`) |

See `.env.example` for the full list with descriptions.

## Performance Tuning

- Increase `DATABASE_POOL_SIZE` (default: 10) for high-concurrency workloads.
- Adjust `TOKEN_EXPIRATION` (default: 3600 s) based on your security policy.
- Set `LOG_LEVEL=WARNING` in production to reduce I/O overhead.
- Use a managed PostgreSQL service (e.g. AWS RDS, GCP Cloud SQL) for production.

---

## Security Hardening

1. **Rotate all default credentials** (`KEYCLOAK_ADMIN_PASSWORD`, `MINIO_SECRET_KEY`, `SECRET_KEY`, database passwords).
2. **Restrict CORS**: set `CORS_ORIGINS` to your actual frontend domain.
3. **Enable TLS**: put Keycloak and the API Gateway behind HTTPS.
4. **Disable DEBUG**: ensure `DEBUG=False` in production.
5. **Enable Keycloak brute-force protection** (enabled by default in the setup script).
6. **Store secrets in a vault** (e.g. HashiCorp Vault, AWS Secrets Manager) rather than plaintext `.env` files in production.
